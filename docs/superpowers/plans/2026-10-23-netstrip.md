# NetStrip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A minimal, Fluent-styled Windows taskbar network speed monitor (↑/↓ inline next to the tray) with a details flyout, daily/monthly totals and data cap, released on GitHub.

**Architecture:** Three projects. `NetStrip.Core` holds all logic behind interfaces, has no WPF/Win32 references, and is unit-tested. `NetStrip.Shell` holds the Win32 integration (counters, taskbar attach, fullscreen detection) via CsWin32. `NetStrip` is the WPF app (strip, flyout, settings) and wires everything together. After Task 1 (skeleton), Tracks A–D run in parallel on disjoint folders. Task 13 integrates them.

**Tech Stack:** C# / .NET 10, WPF Fluent theme (`ThemeMode`), Microsoft.Windows.CsWin32, Microsoft.Toolkit.Uwp.Notifications, System.Text.Json, xUnit, Inno Setup 6, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-netstrip-design.md` (read it; this plan cites its sections as §N)

## Global Constraints

- Target Windows 10 22H2 and Windows 11, x64 and arm64. No admin rights at install or run time.
- TFMs: Core `net10.0`; Shell `net10.0-windows10.0.19041.0`; App `net10.0-windows10.0.19041.0`; Tests `net10.0`.
- `Nullable` enabled, `TreatWarningsAsErrors` true, `LangVersion` latest, everywhere.
- Core must not reference WPF, WinForms, CsWin32 or `Microsoft.Win32.*`.
- Data paths: settings `%AppData%\NetStrip\settings.json`, usage `%AppData%\NetStrip\usage.json`, logs `%LocalAppData%\NetStrip\logs\netstrip-<yyyy-MM-dd>.log` (keep 7).
- Sampling every 1 s; persistence every 60 s and on shutdown; update check ≤ once per 24 h.
- Idle CPU < 0.5 %, working set ≤ 60 MB (§1).
- Single-instance mutex name `Local\NetStrip`. Run key `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value name `NetStrip`.
- Colors: upload teal `#2BB5A8` (light) / `#4FD1C5` (dark); download = system accent.
- No chart library; no third-party UI framework.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Sleep/resume or a stalled timer.** The first tick after a gap of more than 5 s must report 0/0 (resync), not a huge spike. Test: Task 3 `GapOver5s_ResyncsToZero`.
2. **VPN active in `auto` mode.** The best route points at an excluded tunnel adapter, so a naive implementation shows 0 forever. Expected: fall back to the sum of included adapters. Test: Task 3 `Auto_BestRouteExcluded_FallsBackToAll`.
3. **System clock moves backwards or the time zone changes.** Expected: bytes go into the bucket for the new local date, nothing is lost, and nothing throws. Test: Task 4 `ClockMovesBackADay_AddsToEarlierBucket`.
4. **App starts at login before Explorer has created the taskbar.** Expected: wait and attach, not flip to floating mode. Test: Task 6 `StartupGrace_DoesNotCountFailures`.
5. **Very high speeds (10 GbE) and non-English locales.** Expected: the text fits the fixed width and uses the user's decimal separator. Tests: Task 2 `TenGigabit_FitsWidth` and `GermanCulture_UsesCommaSeparator`.

## Task 2: SpeedFormatter

**Files:** Create `src/NetStrip.Core/Formatting/SpeedFormatter.cs`; Test `tests/NetStrip.Core.Tests/Formatting/SpeedFormatterTests.cs`

**Produces:** `public static class SpeedFormatter { string FormatSpeed(long bytesPerSec, SpeedUnits units, CultureInfo? culture = null); string FormatTotal(long bytes, CultureInfo? culture = null); string AccessibleSpeed(long bytesPerSec, SpeedUnits units); }`

Rules (they refine §7's "3 significant digits"):
- Bytes mode uses base 1024 with units KB/s, MB/s, GB/s. Bits mode multiplies by 8 and uses base 1000 with units Kb/s, Mb/s, Gb/s. There is no B/s or b/s unit.
- Below 1 unit, show `0 KB/s` / `0 Kb/s`.
- Number format by value:
  - below 10: 2 decimals
  - below 100: 1 decimal
  - otherwise: 0 decimals
- If the value would display as 1000 or more in a unit, move up to the next unit.
- Totals use B, KB, MB, GB, TB (base 1024) with the same digit rules.

## Task 7: TaskbarHost

**Files:** Create `src/NetStrip.Shell/Taskbar/TaskbarHost.cs`, `src/NetStrip.Shell/Taskbar/TaskbarLocator.cs`, `src/NetStrip.Shell/Taskbar/TaskListProbe.cs`

```csharp
public sealed class TaskbarHost(Func<string /*taskbarKey*/, IStripSurface> createSurface, ILog log) : IDisposable {
    MonitorScope Scope { get; set; }            // re-attaches on change
    void Start();                                // must be called on the UI thread
    void Reposition();                           // public so the app can call it on settings/theme change
    event Action? FallbackActivated;             // raised once per fallback entry
    IReadOnlyDictionary<string, IStripSurface> Surfaces { get; }
```

- `TaskbarLocator` returns `(key, hwnd, TaskbarGeometry)` per taskbar. The key is `"primary"` or the monitor device name. It finds `Shell_TrayWnd` → `TrayNotifyWnd`, and enumerates `Shell_SecondaryTrayWnd`. The edge comes from the taskbar rect relative to its monitor.

- Attach steps: create the surface, `SetParent(surface, taskbarHwnd)`, add `WS_CHILD` and remove `WS_POPUP`, then `Apply(placement)`. Success means `GetParent` returns the taskbar and the window rect is inside the taskbar rect.
- Hooks:

- Fallback: `Apply(new StripPlacement(0, rect, StripMode.Floating, dpi))`, placed just above the tray, then retry per `AttachRetryPolicy`.
